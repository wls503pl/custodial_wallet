# 钱包提现功能

## 一、提现流程

用户提现的整个过程是这样的：

1. **用户提现申请** - 用户说"我要提 100 USDC 到我的钱包"
2. **余额检查** - 系统检查用户有没有 100 USDC
3. **风控检查** - 检查是否异常（比如一天要提 1000 次）
4. **选热钱包** - 从多个热钱包中选一个有钱的
5. **签名** - 签名机对提现交易签名
6. **发送上链** - 将签名后的交易发送给区块链
7. **余额更新** - 用户余额减少，热钱包余额也减少
8. **确认完成** - 用户收到钱

## 二、热钱包管理

### 为什么需要多个热钱包？

简单来说：

- 1 个热钱包处理所有提现 → 容易堵车，交易排队
- 多个热钱包轮流处理 → 负载均衡，交易快

### 如何管理热钱包？

在钱包表中添加 `wallet_type` 字段：

```
wallet_type:
  - 'user'     (用户钱包)
  - 'hot'      (热钱包，用于提现)
  - 'cold'     (冷钱包，存大额资金)
  - 'multisig' (多签钱包，高安全)
```

**选择策略**：

- 选择余额充足的热钱包
- 优先选择最久未使用的（实现轮流）
- 这样避免同一个钱包压力过大

## 三、Nonce 管理（重要！）

### 什么是 Nonce？

Nonce 是交易的序号。一个账户的交易必须按顺序执行：

```
第1笔交易：nonce = 0  ✓ 执行
第2笔交易：nonce = 1  ✓ 执行
第3笔交易：nonce = 2  ✓ 执行
...
```

### 如果 Nonce 出错会怎样？

**图解 Nonce 问题**：

![Nonce 演示](../img/04_withdraw/nonce_match.png)

关键问题：如果第 4 笔交易失败了，第 5 笔交易会**卡住**（即使出再高的费用也无法执行）。这叫 **"Nonce 空洞"**。

### 如何管理 Nonce？

创建 `wallet_nonces` 表记录每个热钱包的当前 nonce：

| 字段         | 说明          |
| ------------ | ------------- |
| wallet_id    | 热钱包 ID     |
| nonce        | 当前 nonce 值 |
| last_used_at | 最后使用时间  |

**操作流程**：

1. 初始化：从链上获取当前 nonce
2. 每次使用：nonce + 1，保存到数据库
3. 下次提现：选择 last_used_at 最久远的热钱包（轮流使用）

## 四、手续费设置

### 问题：用户该付多少手续费？

如果每次让用户自己设置 → 用户体验差
如果手续费不足 → 交易可能被拒

**解决方案**：固定手续费 + 动态 Gas

### 方案 1：固定提现手续费

在 `tokens` 表添加字段：

| 字段                | 说明               |
| ------------------- | ------------------ |
| withdraw_fee        | 提现手续费（固定） |
| min_withdraw_amount | 最小提现金额       |

**例子**：

- USDC 的提现手续费：0.5 USDC
- 最小提现金额：5 USDC
- 用户提现 100 USDC → 实际转账 99.5 USDC

**好处**：

- 用户可预期
- 交易所能赚手续费
- 操作简单

### 方案 2：动态 Gas 跟随

实际的链上 Gas 费是波动的，需要动态调整：

```
手续费 = Gas 数量 × (基础费 + 优先费)
```

**实现方法**：

1. 通过 RPC 接口 `eth_feeHistory` 查询最近 20 个区块的费率
2. 取中位数作为基础费
3. 为了快速打包，可以加 20% 的溢价（buffer）
4. 实时调整，不浪费

**动态调整的好处**：

- 网络不拥堵 → 费用低
- 网络拥堵 → 费用高
- 既保证到账速度，又不浪费

## 五、Gas 费详解

### EIP-1559 交易的 Gas 结构

```
支付手续费 = gasLimit × (baseFeePerGas + priorityFeePerGas)
```

三个关键参数：

| 参数              | 说明                 | 例子                 |
| ----------------- | -------------------- | -------------------- |
| gasLimit          | 交易最多消耗多少 Gas | ETH 转账：21,000 Gas |
| baseFeePerGas     | 基础费（由网络决定） | 50 Gwei              |
| priorityFeePerGas | 小费（给矿工的）     | 2 Gwei               |

### 如何设置这些参数？

**推荐方案**：

1. gasLimit：固定值（在 tokens 表配置）
2. baseFeePerGas：取最新区块的值
3. priorityFeePerGas：取最近 20 个区块的 70 分位数（快速打包但不过度）
4. maxFeePerGas = baseFeePerGas × 2 + priorityFeePerGas

这样既能适应网络波动，又不会浪费钱。

## 六、批量提现优化（高级）

### 普通方式的问题

热钱包（EOA 账户）每次只能发一笔交易，每笔都要付 21,000 Gas 的基础费。

如果短时间要处理 100 笔提现：

- 需要发 100 笔交易
- 100 × 21,000 = 2.1M Gas（很贵！）

### 解决方案

**方案 1：使用 EIP-7702 智能账户**

- 将普通账户升级为智能账户
- 支持批量交易
- Gas 费大幅下降

**方案 2：金库合约**

- 写一个金库合约
- 签名机签名调用金库的批量转账函数
- 一笔交易处理多个提现

**方案 3：用其他链**

- Bitcoin 和 Solana 默认支持批量交易
- 不需要特殊处理

## 七、数据库设计

### withdraws 表（提现记录）

| 字段         | 说明                         |
| ------------ | ---------------------------- |
| id           | 主键                         |
| user_id      | 用户 ID                      |
| from_address | 热钱包地址                   |
| to_address   | 用户的提现地址               |
| amount       | 提现金额                     |
| fee          | 手续费                       |
| status       | pending / confirmed / failed |
| tx_hash      | 交易哈希                     |
| nonce        | 交易序号                     |
| gas_used     | 实际消耗的 Gas               |

### 状态流转

```
user_withdraw_request
    ↓
signing（签名中）
    ↓
pending（已发送，等待确认）
    ↓
confirmed（已确认）
```

如果出错：

```
failed（失败）+ error_message（错误原因）
```

### 资金流水关联

在 `credits` 表（资金流水表）中：

- 当提现时，为用户和热钱包各添加一条记录
- 用户的 amount 为负（扣款）
- 热钱包的 amount 也为负（转出）
- 这样聚合就能算出每个地址的余额

## 八、核心总结

| 问题                 | 解决方案                      |
| -------------------- | ----------------------------- |
| 多笔提现怎么不堵车？ | 多个热钱包轮流处理            |
| Nonce 怎么管理？     | 数据库记录 + 轮流选择         |
| 手续费怎么定？       | 固定用户手续费 + 动态跟踪 Gas |
| 怎么保证快速到账？   | 动态跟踪链上费率，适度加溢价  |
| 批量提现怎么优化？   | 用 EIP-7702 或金库合约        |
| 怎么保证对账？       | 记录到资金流水表 (credits)    |

## 九、提现的最佳实践

1. **热钱包**

   - 多个热钱包并轮流使用
   - 避免单点拥堵和 Nonce 冲突

2. **Nonce 管理**

   - 数据库精确追踪每个热钱包的 Nonce
   - 确保交易顺序正确

3. **手续费**

   - 用户侧：固定手续费（可预期）
   - 链上侧：动态跟踪真实 Gas 费（不浪费）

4. **性能优化**

   - 高并发场景考虑批量提现
   - 根据用户等级调整 Gas（VIP 优先）
   - 超时自动提升 Gas 重发

5. **风控**（后续专题）
   - 异常地址检测
   - 提现限额控制
   - 签名许可机制
