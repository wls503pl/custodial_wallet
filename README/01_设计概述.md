# 交易所钱包系统详解

## 什么是交易所钱包系统？

想象你在交易所开了个账户，交易所要帮你做三件事：

1. **生成一个钱包地址** - 让你能充钱进来
2. **记录你的余额** - 你有多少钱交易所要记账
3. **帮你转账** - 你要提现时，交易所帮你把钱转出去

交易所钱包系统就是做这三件事的系统。

---

## 设计 1：最简单的方案

### 需要这些部分

- **充值服务** = 不停监听区块链，看有没有用户充钱进来
- **提现服务** = 帮用户把钱转出去
- **数据库** = 记录每个用户有多少钱
- **业务接口** = 给用户分配钱包地址

### 用户充值流程

![充值流程基础版](../img/preliminary_design/deposit.png)

```
1️⃣ 用户向业务接口说："给我一个钱包地址"
   → 业务接口分配一个地址给用户

2️⃣ 用户向这个地址转账 100 U
   → 在区块链上确认了这笔交易

3️⃣ 充值服务监听到了这个交易
   → "哦，这个地址是用户A的，他充了100U"

4️⃣ 充值服务把这个记录到数据库
   → 用户A的余额 = 100U
```

### 用户提现流程

![提现流程基础版](../img/preliminary_design/withdraw.png)

```
1️⃣ 用户说："我要提现 50U"

2️⃣ 提现服务收到请求
   → 准备一个转账交易："从交易所账号转50U给用户"

3️⃣ 提现服务把交易签名后，发到区块链

4️⃣ 区块链确认转账成功

5️⃣ 用户收到50U，数据库更新余额
   → 用户A的余额 = 50U
```

### 问题来了 ⚠️

**私钥直接存在数据库里！**

如果黑客黑了数据库，就能拿到所有用户的私钥，然后把所有的钱都转走。这太危险了！

---

## 设计 2：加入签名机和资金调度

### 核心思想

不要把私钥存在容易被黑的地方，要：

1. **把私钥放在一个独立的、不连网的安全机器里** = 签名机
2. **把钱分散存放在不同的钱包里** = 资金分级管理

### 两个新的东西

#### 1. 签名机（保险柜）

```
签名机 = 一台独立的、不连网的机器

它做什么：
✅ 存放所有的私钥（像保险柜一样）
✅ 当需要签名时，才会签
✅ 签完名后，返回签名数据

它的安全性：
🔐 不连网 → 黑客进不来
🔐 只负责签名 → 即使被黑也只能签名，转不了账
🔐 私钥永远不离开这台机器
```

#### 2. 资金调度服务（自动搬钱的机器）

```
资金调度服务做什么：
不停监控各个钱包里有多少钱，
然后自动把钱从低级钱包转移到高级钱包。

为什么要这样做：
💡 分散风险 - 钱不要都放在一个地方
💡 多人管理 - 高级钱包需要多个人同意才能用
💡 保证流动性 - 低级钱包随时有钱可用
```

### 资金怎么分级管理？

```
                    一级钱包 (最安全)
                    ↑ 需要5/9个人同意
                    |
        当钱 > 300万U 时转移
                    |
                    二级钱包 (很安全)
                    ↑ 需要3/5个人同意
                    |
        当钱 > 50万U 时转移
                    |
                  热钱包 (相对安全)
                    ↑ 快速使用
                    |
        当钱 > 1000U 时转移
                    |
                 用户账号 (小钱包)
                   (入口)
```

**简单说：** 钱进来时，一点点往上转，越往上越安全。需要用钱时，再从上往下转。

### 完整流程

![签名机和资金调度](../img/preliminary_design/SignatureMachine_FundAllocation.png)

#### 用户开户

```
1. 业务接口调用签名机："帮我生成一个账号"
2. 签名机生成账号，存在数据库
   （注意：私钥不存在数据库，只在签名机里）
```

#### 用户充值

```
1. 用户得到地址 → 转账进来 → 充值服务监听到
2. 充值服务记录到数据库
3. 资金调度服务监控到用户账号有1000U
   → 自动转到热钱包（资金归集）
```

#### 用户提现

```
1. 用户申请提现
2. 提现服务向签名机请求："帮我签一个转账交易"
3. 签名机用热钱包的私钥签名
4. 提现服务拿到签名，广播到区块链
5. 区块链确认后，完成转账，用户收到钱
```

## 设计 3：加入风控（防止洗钱）

### 新问题

即使有了签名机和资金分级，还有个问题：

**用户可能用交易所来洗钱！**

```
黑客可能这样做：
1. 充值一笔黑钱进来（可能是非法所得）
2. 立即提现到自己的账户
3. 这样黑钱就"洗白"了
```

### 解决方案：风控模块

```
风控模块 = 黑名单检查机器

充值时检查：
"这笔钱来自哪个地址（EOA有没有被标记）？"
"这个地址在黑名单里吗？"
"是的话 → 拒绝入账"
"不是 → 允许入账"

提现时检查：
"用户要转到哪个地址（EOA有没有被标记）？"
"这个地址在黑名单里吗？"
"是的话 → 拒绝提现"
"不是 → 允许提现"
```

注：KYC(Know Your Customer) 有专门的服务商，不在这里讨论

### 流程变成这样

![加入风控](../img/preliminary_design/RiskManagement.png)

```
充值流程：
用户充值 → 风控检查 → 没问题才入账到数据库

提现流程：
用户提现 → 风控检查 → 没问题才请求签名机 → 签名转账
```

---

## 设计 4：独立风控系统（最安全的方案）

### 新问题又来了

如果风控模块和业务系统在一起，黑客黑了业务系统，就能绕过风控。

**解决方案：** 让风控单独运行，独立验证

### 三重签名保护

```
┌─────────────────────────────────────────┐
│ 提现流程                                   │
├─────────────────────────────────────────┤
│ 1️⃣ 用户发起提现                          │
│    ↓                                      │
│ 2️⃣ 业务系统对数据签名                    │
│    "我确认用户要提现100U"                │
│    ↓                                      │
│ 3️⃣ 风控系统独立验证并签名               │
│    "我检查了，这个地址没问题"            │
│    ↓                                      │
│ 4️⃣ 签名机最终签名                       │
│    "我用私钥签名了"                      │
│    ↓                                      │
│ 5️⃣ 有了三个签名，交易才能执行           │
│    → 转账成功                             │
└─────────────────────────────────────────┘
```

**好处：** 即使黑客黑了业务系统，风控和签名机还会验证。要想成功作恶，需要同时黑掉三个独立的系统，几乎不可能。

### 完整架构图

![最终架构设计](../img/preliminary_design/OverallSystem.png)

#### 各个模块的职责

| 模块         | 职责         | 权限                           |
| ------------ | ------------ | ------------------------------ |
| **充值服务** | 监听充值交易 | 只能写余额到 DB                |
| **提现服务** | 处理提现请求 | 必须先过风控，才能请求签名     |
| **风控系统** | 黑名单检查   | 独立验证，不受业务系统影响     |
| **签名机**   | 私钥签名     | 最后的守门员                   |
| **资金调度** | 自动转账     | 监控余额，执行自动转移         |
| **数据库**   | 记录数据     | 充值直接写，提现需要签名后才写 |

## 资金流向总结

### 用户充值

```
用户 → 转账到分配的账号 → 充值服务监听到
→ 风控检查 ✓ → 记录到数据库
→ 资金调度监控 → 自动转移到热钱包
→ 热钱包超额时 → 转移到二级钱包
→ 二级钱包超额时 → 转移到一级钱包
```

### 用户提现

```
用户 → 提现请求 → 业务系统签名
→ 风控系统验证 ✓ → 风控系统签名
→ 请求签名机 → 签名机用私钥签名
→ 三个签名都有 ✓ → 广播到区块链
→ 用户收到钱 → 数据库更新余额
```

### 资金调度

```
监控用户账号 → 超过1000U → 转移到热钱包
监控热钱包 → 超过50万U → 转移到二级钱包
监控二级钱包 → 超过300万U → 转移到一级钱包
需要钱时 → 从上级钱包转回下级钱包
```

## 核心安全原则

### 分散（Decentralization）

- 私钥分散存放（用户签名机、热钱包签名机）
- 钱分散存放（多个等级的钱包）
- 权力分散（需要多个系统同意才能转账）

### 隔离（Isolation）

- 业务系统和签名机分离
- 风控系统独立运行
- 高安全钱包需要多个人同意

### 验证（Verification）

- 充值前检查来源
- 提现前检查目标
- 多个系统三重验证签名

---

## 为什么要这么复杂？

你可能会问："为什么不能更简单？"

**因为：**

- 🔐 **安全性** - 一个地方出问题，整个系统崩溃
- 💰 **资金量大** - 交易所管理着大量用户的资金
- 🎯 **风险高** - 一次被黑就损失巨大
- ⚖️ **合规** - 需要防洗钱、防非法活动

每一层防御都是必要的：

- 签名机防止私钥泄露
- 资金分级降低单点风险
- 风控防止洗钱
- 独立验证防止内部作恶

---

## 总结

```
简单说：

第一层防守 = 签名机
 └─ 私钥安全存放

第二层防守 = 资金分级
 └─ 钱不要都放一个地方

第三层防守 = 风控检查
 └─ 拦截黑钱和非法地址

第四层防守 = 独立验证
 └─ 多个系统各自签名确认

```
